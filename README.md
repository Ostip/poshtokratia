# Poshtokratia

Сайт Poshtokratia: акаунти, історії, листи, меми та заходи спільноти. «Залізна Зміна» — другорядна назва спільноти.

## Модерація листів

Листи з’являються у спільній стрічці та можуть бути прочитані іншими, навіть якщо відправника позначено анонімним. Читачі можуть поскаржитися на лист; звернення зберігається без імені чи IP відправника та доступне адміністраторам у студії → «Модерація» → «Скарги». Адміністратор може залишити лист або видалити його.

## Як додавати заходи (студія `/admin`)

1. Відкрий `https://твій-сайт.onrender.com/admin`.
2. Введи **ключ адміністратора** — це значення змінної `ADMIN_PASSWORD` на Render.
3. У вкладці «Заходи» встав текст зі смайликами (як у Telegram), вибери категорію, дату, місце — справа видно, як це буде на сайті.
4. Натисни «Опублікувати» — захід одразу зʼявляється в розділі **Заходи** на головній (відкриті сторінки оновлюються самі протягом хвилини).

Можна: зберігати чернетки (їх не видно людям), закріплювати зверху, додавати обкладинку, редагувати, дублювати, видаляти. Текст автоматично зберігається як чернетка в браузері.
У тексті працює `**жирний**`, посилання стають клікабельними.

> Якщо `ADMIN_PASSWORD` не задано — адмінка вимкнена (так безпечніше). Задай його: Render → сервіс → Environment → Add → `ADMIN_PASSWORD` = довгий пароль (12+ символів).

## Окремий сайт для адміна (Render Static Site)

Студія заходів може жити на **власній адресі**, окремо від публічного сайту (наприклад `poshtokratia-admin.onrender.com`). Вона лежить у папці `admin-site/`.

1. Render → **New → Static Site** → той самий репозиторій, гілка `main`.
2. **Publish Directory:** `admin-site` (Build Command лишити порожнім). Назва, наприклад, `poshtokratia-admin`.
3. Скопіюй адресу нового сайту й додай її в **основний** сервіс (Environment): `ADMIN_ORIGIN` = `https://poshtokratia-admin.onrender.com` (без слеша в кінці).
4. Якщо адреса основного сайту не `poshtokratia.onrender.com` — зміни її у файлі `admin-site/config.js`.
5. За бажанням додай на основному сервісі `ADMIN_PAGE=off` — тоді `/admin` на публічному сайті зникне, студія буде лише на окремій адресі.

Ключ адміністратора той самий (`ADMIN_PASSWORD` на основному сервісі). Студію теж можна «встановити» на телефон як застосунок.

## Смартфони й планшети (головний пріоритет)

Сайт зроблено «смартфон-first»:
- **нижнє меню як у застосунку** (Головна · Заходи · Історії · Пошта · Меми · Профіль) на екранах до 820 px; на ПК — звичайне верхнє меню;
- вікна на телефоні — **нижні шторки** (закриваються свайпом вниз, хрестиком або кнопкою «Назад» телефона — сайт не закривається);
- великі кнопки (від 44 px), поля вводу 16 px (iOS не «наближає» сторінку), підтримка «чубчика» й нижньої смужки iPhone, вібрація при лайку;
- **установка на головний екран** (PWA): кнопка «Встановити» у блоці «Наш застосунок»; працює й без інтернету (відкриється оболонка сайту);
- адмінка `/admin` теж зручна з телефона: кнопка «Опублікувати» закріплена внизу.

Іконки застосунку: `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon.png` — можна замінити на свій логотип (ті самі імена й розміри).

## Підписки

Люди можуть підписуватись одне на одного: блок «Люди спільноти» над історіями, кнопка «Підписатися» в профілі, списки підписників/підписок, фільтр історій «Підписки».
Коли хтось підписується на тебе, сповіщення зʼявляється у дзвіночку біля профілю. Відкрий його, щоб переглянути підписника та перейти до його профілю; переглянуті сповіщення позначаються прочитаними.

## Публікації з Telegram

Сайт може автоматично показувати нові дописи каналу Poshtokratia у розділі «З Telegram». Щоб увімкнути інтеграцію:

1. Створи бота через `@BotFather` і додай його адміністратором каналу з правом бачити дописи.
2. Визнач числовий ID каналу (зазвичай починається з `-100`). Його можна прочитати в `channel_post.chat.id` у відповіді Telegram Bot API `getUpdates`, поки webhook ще не налаштований.
3. У Render → вебсервіс → **Environment** додай `TELEGRAM_BOT_TOKEN` (токен бота), `TELEGRAM_CHANNEL_ID` (ID каналу) і `TELEGRAM_WEBHOOK_SECRET` (випадковий секрет із літер, цифр, `_` або `-`, до 256 символів).
4. Перезапусти сервіс. За наявності `RENDER_EXTERNAL_URL` сервер сам зареєструє HTTPS webhook у Telegram. Якщо потрібно, можна задати повну адресу через `TELEGRAM_WEBHOOK_URL`; шлях має бути `/api/telegram/webhook`.

Після налаштування стан інтеграції видно в розділі «З Telegram». Публікуються лише нові дописи й редагування після підключення; старі публікації не імпортуються, а видалення з каналу не синхронізується. Текст і підпис до медіа показуються як текст; фото до 2 МБ зберігаються на сайті, більші фото й інші типи медіа відображаються посиланням на оригінал у Telegram. Сайт зберігає останні 100 дописів. Для роботи фото потрібне постійне сховище — Postgres через `DATABASE_URL` або інше довговічне сховище для `uploads/`.

## Акаунти

Реєстрація: імʼя, нікнейм (`@nick` — особиста сторінка), email, пароль (мін. 8). Є профіль (фото, «про себе»), зміна пароля, видалення акаунта, лайки, відмітка «Піду» на заходах. Історії та меми публікують лише зареєстровані; листи — можна й анонімно.
Старі акаунти працюють: при першому вході пароль автоматично переводиться на безпечніший хеш (scrypt), а нікнейм створюється з email.

## Запуск локально

```bash
npm start            # http://localhost:3000
ADMIN_PASSWORD=мій-ключ npm start
```

## Змінні середовища

| Змінна | Для чого |
|---|---|
| `ADMIN_PASSWORD` | ключ для `/admin` (обовʼязково) |
| `SESSION_SECRET` | підпис сесій (Render згенерує сам через `render.yaml`) |
| `ADMIN_ORIGIN` | адреса окремого сайту студії (для зв'язку з API) |
| `ADMIN_PAGE` | `off` — вимкнути `/admin` на основному сайті |
| `DATABASE_URL` | рядок підключення до Postgres (щоб дані не зникали) |
| `DATA_DIR` | куди писати локальні `data.json` і `uploads/` (кеш/файловий режим) |
| `TELEGRAM_BOT_TOKEN` | токен бота для webhook (секрет; лише на сервері) |
| `TELEGRAM_CHANNEL_ID` | числовий ID каналу, наприклад `-100…` |
| `TELEGRAM_WEBHOOK_SECRET` | секрет для перевірки запитів webhook |
| `TELEGRAM_WEBHOOK_URL` | необов’язкова повна HTTPS-адреса `/api/telegram/webhook`; за замовчуванням береться з `RENDER_EXTERNAL_URL` |

## База даних (Postgres)

Якщо на сервісі задано змінну **`DATABASE_URL`**, усе зберігається в Postgres: акаунти, підписки, історії, листи, меми, заходи **і фото**. Деплой чи перезапуск нічого не стирає. Таблиці (`zz_state`, `zz_images`) створюються самі — вручну нічого робити не треба (файли `postgres-setup.sql` і `migrate-data.js` більше не потрібні).

- Перевірка: відкрий `https://твій-сайт/api/health` — має бути `"storage":"postgres"`. У студії (вкладка «Огляд») теж видно, де лежать дані.
- Якщо база порожня, а поруч є `data.json`/`uploads/`, при першому запуску вони **імпортуються** автоматично.
- Якщо `DATABASE_URL` задано, але база недоступна — сервер **не запускається** і пише причину в Logs (щоб не збирати дані «в нікуди»). Попередня версія сайту при цьому лишається працювати.
- Без `DATABASE_URL` сайт працює як раніше, у файлах (на безкоштовному Render вони стираються).
- Резервна копія: студія → «Огляд» → «Завантажити резервну копію» (JSON, без самих фото).

⚠️ Безкоштовна база Render **видаляється через 30 днів** після створення. Для постійного безкоштовного варіанта підійдуть Neon або Supabase — просто встав їхній рядок підключення у `DATABASE_URL`.

## Безпека (що вже зроблено)
- сесії в HttpOnly-cookie, паролі scrypt, ліміти на вхід/реєстрацію/адмін-ключ;
- фото перевіряються за вмістом і лежать окремими файлами (`uploads/`), SVG заборонені;
- вихідний код сервера й `data.json` не віддаються з сайту; перевірка Origin на всіх змінах даних;
- видаляти чужий контент може лише адмін.
